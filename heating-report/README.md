# Отчёт по начислению отопления, сезон 2026/27 (КОІН)

Google Apps Script для таблицы «Отопление сезон 2025/26»
(`1YFxvAx2aJlmkTUnIfb65SZ-mXL75CCxdAVrHuENisQo`). Версия структуры листов — 4.

## Установка

1. Откройте таблицу и выберите **Расширения → Apps Script**.
2. **Удалите весь старый код** во всех файлах `.gs`. Если оставить старый `onOpen`, будут два меню, и неясно, какая функция сработает.
3. Вставьте содержимое `Code.gs` и сохраните проект.
4. Обновите таблицу (F5). Появится меню **КОІН → Отопление**.
5. Выполните пункт **1. Создать / обновить листы** и разрешите доступ.

## Что произойдёт со старыми листами v3

У старых листов НАСТРОЙКИ, ВВОД и ОТЧЁТ нет метки версии, поэтому скрипт переименует их в `…_старые` и создаст новые:

- **НАСТРОЙКИ.** Параметры переносятся по названию: объекты, веса, план сверхлимита 694 634 и коэффициент СПЧ 0,35.
- **ВВОД.** Данные не переносятся. В старом листе они стояли в прежнем порядке колонок: например, площадь 25 094,84 попала в колонку «в т.ч. сверхлимит». Лимнос нужно заново ввести в новый ВВОД по шапке.
- **ОТЧЁТ, ДЕТАЛИ РАСЧЁТА.** Создаются пустыми и заполняются командой «Пересчитать отчёт».

Лист «ОТЧЁТ (копия)» и все остальные листы скрипт не трогает.

## Меню

| Пункт | Что делает |
|---|---|
| 1. Создать / обновить листы | Создаёт недостающие листы. Устаревшие листы архивирует и пересоздаёт |
| 2. Пересчитать отчёт | Заполняет листы ОТЧЁТ и ДЕТАЛИ РАСЧЁТА |
| 3. Проверить настройки | Показывает версии листов, режим сглаживания, подпись строки и пять чисел содержания котельной по каждому ЖК |
| 4. Пересоздать листы заново | Принудительная пересборка всех четырёх листов с переносом параметров |

## ФСО + МЗК

Параметр «Распределение ФСО+МЗК» в НАСТРОЙКАХ:

- **пропорционально газу** (по умолчанию). ФСО+МЗК входит в цену Гкал и в тарифы без счётчика и СПЧ в той же пропорции, что и газ, то есть по тарифам распределяется вся база. «Содержание котельной» в отчёте равно строке сметы.
- **в содержание котельной**. ФСО+МЗК делится на всю площадь и прибавляется к «Содержанию котельной», как в исходном ТЗ.

## Профиль сглаживания

Параметр «Профиль сглаживания применять к» в НАСТРОЙКАХ:

- **квитанции без счётчика** (по умолчанию). Веса 0,6 / 1 / 1 / 1 / 0,9 задают соотношение квитанции квартиры без счётчика: содержание котельной + газ, грн/м². Месяцы, где квитанция уже выше целевой даже без сверхлимита, добавку не получают.
- **базе распределения**. Веса задают соотношение сумм к распределению, как в исходном ТЗ. Пример Лимноса из ТЗ проверяется в этом режиме.

## Лист ДЕТАЛИ РАСЧЁТА

Числа в строках расчёта записаны формулами со ссылками на ВВОД, НАСТРОЙКИ, сезонную смету и блок сверки сверхлимита. Внизу листа есть блок «Как считается» с формулами словами. `node heating-report/test/formulas.js` проверяет, что формулы дают те же числа, что и скрипт.

## Как считается сверхлимит в середине сезона

Пока март не введён, сумма к разнесению равна большему из двух чисел: плана из НАСТРОЕК и факта в уже введённых счетах. В режиме «профиль квитанции» базы ещё не введённых месяцев оцениваются по профилю введённых. Поэтому добавки прошлых месяцев уточняются с каждым новым счётом.

Когда введён март, сумма к разнесению равна факту сезона. Если параметр «Доводить сверхлимит в последнем месяце» = «Да», март получает разницу «факт сезона − уже разнесённое». Если тариф прошлого месяца уже выставлен в квитанции, сверяйтесь с листом ДЕТАЛИ РАСЧЁТА: в нём есть блок сверки.

## Проверка логики

`node heating-report/test/run.js` проверяет расчёт без Google Таблиц:

- пример Лимноса из ТЗ: добавки 114 776 · 84 871 · 0 · 338 461 · 156 527, сумма баз = сумма счетов = 1 891 976,02;
- контроль расхождения;
- учёт ЛП только по м²;
- дубли строк и лаг начисления.

Функцию `testSmoothingLimnos` можно запустить и прямо из редактора Apps Script, результат появится в журнале.
